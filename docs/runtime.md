# API 与构建运行

现有 UI 的模板、样式、文案及交互结构保持不变，页面数据已由浏览器 Mock 切换到真实 API。服务端是唯一业务状态来源；项目、任务、版本、产物和设置持久化到 SQLite。浏览器刷新不会重置业务数据。公开页面仅请求 `/api/public/*`，不读取会话。

## 本机开发

Node.js 24 / npm 11，系统需提供 Git、Bash、Node.js、OpenSSH 客户端（`ssh-keygen`、`ssh-keyscan`、`ssh`），以及项目脚本实际需要的工具。无需 Docker。

```bash
npm ci
cp -n apps/server/.env.template apps/server/.env
chmod 600 apps/server/.env
```

首次初始化时执行 `openssl rand -base64 32`，将结果填入 `apps/server/.env` 的 `BUILDER_SECRET_KEY` 后再启动；已有配置或恢复数据库时保留原主密钥。模板用于说明变量，服务实际读取 `.env`，两者的关系与完整启动步骤见 [README](../README.md#环境与启动)。

```bash
npm run dev
```

`BUILDER_RUNNER=local` 是开发默认值。它会执行管理员配置的真实构建脚本，必须只接入受信任仓库和脚本。每个项目使用一个 `DATA_DIR/builds/project-<项目ID>/`。源码在 `source/`，Git 元数据和构建 HOME 在 `workspace/`，任务日志、脚本和校验清单在 `jobs/<任务ID>/`，最终文件在 `outputs/<任务ID>/<原文件名>`。同项目串行，不同项目可占用不同槽位。不继承服务进程的密码或 token 环境变量，不读取用户 Git 全局配置。**本机模式没有操作系统级隔离，脚本仍拥有运行服务的本机账号权限和网络访问能力。** 不用它运行不受信任代码，也不能把本轮本机测试记为容器安全验收。

本机打包工具有路径长度限制时，可将 `BUILDER_WORKSPACE_DIR` 设为 `DATA_DIR` 之外、服务账号独占（0700）的短目录。平台按数据目录和项目分隔工作区，仅移动源码与缓存。启用时，已有缓存的项目会在下一次构建时通过同一文件系统上的重命名迁移。保留该配置以继续复用缓存；数据库、历史日志、备份和已发布文件仍使用原位置。Docker 使用容器内的固定路径。

升级时，在停止遗留任务后，将任务对应的旧目录移入项目历史目录；旧产物移入 outputs 并保留已有下载链接。旧数字文件保留原存储名，新构建保留原始文件名。同一任务的目录冲突会暂停恢复，不覆盖。历史源码按原任务生命周期清理，不作为新任务的可信缓存。

脚本可将最终安装包写入或复制到 `"$OUTPUT_DIR"`。该变量指向本次任务的空目录，成功后平台校验并发布到项目的 `outputs/<任务ID>/`，构建脚本不需要拼接宿主路径。已有脚本继续从配置的“产物路径”收集；脚本使用该方式时负责确保该路径只包含本次需要发布的文件。备份包含各版本产物与清单，不包含可重建的项目共享工作区。

发起构建时“使用构建缓存”按当前账号和项目记住本浏览器上次的勾选状态，没有记录时默认勾选。分支和标签在任务执行时一律从远端拉取，并按本次取得的提交构建；远端拉取失败则结束任务。不勾选时恢复受 Git 跟踪的源码，清理 Git 忽略的文件/目录及项目包管理器 HOME 缓存；同一引用的普通未跟踪文件不主动清除。勾选且缓存匹配时保留忽略的依赖和包管理器 HOME 缓存。首次使用或更改仓库、引用、绑定的密钥或执行环境会重新初始化。两种模式都完整执行项目脚本（含其安装步骤）。

默认管理员仅首次创建 `admin / admin123456`，请重置密码。不会创建演示普通账号；需管理员在现有用户页创建。全局演示环境横条和登录页演示账号填充区已移除，数据及构建实际来自服务端。

仓库地址支持 HTTPS、SSH 和 `git@host:path`。不接受地址内嵌密码。HTTPS 仓库匿名拉取；SSH 仓库由管理员在设置页生成或导入无口令私钥，在代码托管平台授权公钥，然后在项目配置中绑定密钥。执行器不转交本机 SSH agent 或登录账号的默认 Git 凭据，也不支持账号密码、HTTPS token 或带口令私钥。

首次使用密钥功能前，在服务端环境配置 `BUILDER_SECRET_KEY`。使用 `openssl rand -base64 32` 生成 32 字节主密钥，写入受限的服务配置文件（0600），配置目录使用 0700。不要写入 Git、构建脚本或日志。私钥以 AES-256-GCM 加密后写入数据库；主密钥缺失或格式错误时密钥/主机管理接口返回 503，其余功能正常。主密钥错误时无法解密已有私钥，不会回退明文。

数据库备份包含加密私钥和已记录的主机公钥，**主密钥必须与数据库备份分开保管**。恢复副本时配置原主密钥；丢失原主密钥意味着全部原私钥不可用，需要重新生成/导入并更新代码托管平台授权。当前不提供主密钥轮换工具。

凭据临时目录位于 `DATA_DIR/ssh-temporary`，与源码目录分开，目录 0700、文件 0600。仅远端 Git 步骤得到凭据；Docker 只读挂载 `/run/creds`；首次连接单独挂载可写的临时主机公钥文件。构建脚本容器不挂载这两处文件。每步成功、失败、取消或超时后删除，启动先核对遗留任务进程/容器，再清理临时凭据。**本机模式下，同一服务账号的并发脚本仍有宿主权限，不能据此声称私钥具备操作系统级隔离。**

首次成功与未记录的主机执行远端 Git 操作后，系统自动记录该主机和端口的 SSH 公钥。首次连接依赖当时的网络；后续公钥不匹配时拒绝连接。设置页无需手动添加主机。旧版主机管理接口继续供运维兼容使用；轮换时应先从可信渠道核实新公钥，再通过管理员接口更新。现有扫描接口仍只连接确认的公网地址。

## 运行规则

- 「测试拉取」只验证指定分支或标签能否实际拉取，不固定构建提交，也不阻止直接入队。入队保存分支或标签、构建配置快照及操作者 ID；任务开始时拉取所选分支或标签，记录实际提交后再执行脚本。拉取失败时任务结束。旧客户端指定 SHA 的请求保留原流程。删除后重建同名用户不能继承原用户任务的操作权。
- 创建任务使用 `Idempotency-Key`；请求结果不确定时应保留并重用原 key。服务端拒绝同一 key 对应不同输入；删除任务后保留 7 天的请求回执，防止迟到重试重新创建构建，新任务使用新 key。
- 单调度器在数据库 Worker 的短事务里按全局序号领取。运行及停止中任务都占槽位；调低并行上限不停止当前任务。
- 三个阶段：拉取源码、执行 `bash -ex build.sh`、收集产物。日志纯文本存储，单任务日志上限 10 MB；超出限额、非零退出、超时或缺少产物都明确失败。
- 产物最多 100 个、总计 768 MiB。拒绝路径穿越、符号链接、硬链接和非普通文件；收集后计算大小与 SHA-256，原子发布文件目录，再写版本记录。
- 管理员可在项目卡片菜单选择“删除项目”，通过 Popconfirm 二次确认后删除项目及全部排队/已结束构建、源码副本、日志、版本和产物；公开下载立即失效。清理覆盖按任务编号和按仓库/分支命名的构建目录，不修改独立备份。有运行/停止中的任务或正在拉取时拒绝，需先停止/等待。共享 SSH 密钥和其他项目正在引用的图标保留。清理失败时项目显示“删除未完成”并可重试，重启自动继续；未完成文件清理前保留项目记录。
- 停止时先记为 `canceling`，终止任务进程组，确认退出后再释放槽位。执行中任务不能删除。删除先隐藏版本、拒绝新下载，再删除该任务文件，最后删除数据库记录。正在下载时返回冲突，可在下载结束后重试；失败清理在重启时继续。
- 重启核对未完成任务及产物清单，不能确认进程身份或数据提交结果时保留占用并暂停领取。调度器锁阻止重复启动；若启动阶段被强制中断留下 `.guard`，须先确认无服务进程，再处理该锁。
- 项目删除会清理该项目的任务目录（含源码、依赖及任务 HOME 缓存）和带项目编号的拉取临时目录。旧版没有项目编号的拉取目录仍由服务在启动时恢复清理，不按仓库名称猜测归属。更换图标会清理不再引用的旧图标；浏览器成功刷新项目列表后会清除已删除项目的分支偏好和任务日志缓存。系统审计、用于阻止重复构建的请求标记及独立备份按原有策略保留。
- 服务空闲时可执行管理员接口 `POST /api/maintenance/backup`（带会话、Origin、CSRF），备份保存到 `DATA_DIR/backups/<id>`，备份期间拒绝业务写入。任务仍在执行或清理时拒绝开始备份。

离线恢复到全新目录，禁止覆盖在线数据：

```bash
npm run build -w @builder/server
node apps/server/dist/tools/restore.js /absolute/backup/id /absolute/new-data-dir
```

恢复前检查 SQLite 完整性、外键及全部公开产物的大小和 SHA-256；随后以独立端口和 `DATA_DIR` 启动验证，再安排切换。脚本失败时不自动切换数据目录。

## 服务器 Docker 模式

应用和任务是不同的镜像。完整部署及升级见 [Docker 部署手册](../deploy/README.md)。服务器配置使用 `BUILDER_RUNNER=docker`，`NODE_ENV=production` 禁止本机模式。

```bash
docker build -t builder-runtime:node24 -f tools/Dockerfile .
```

固定镜像包含 Node.js、Bash、Git；其他打包工具由部署方固定加入。构建容器非 root、只读根文件系统、无 capabilities、无宿主凭据或引擎 socket 挂载；只挂载该任务目录，限制 2 CPU、2 GB 内存、256 进程和临时目录空间。Git 拉取和构建默认使用普通 Docker 网络。

管理员可在「设置 → 构建依赖源」填写一个 HTTP 或 HTTPS Node 包源（例如 `https://registry.npmmirror.com`）。新提交的任务保存当时的地址，并将它作为 npm、pnpm、Yarn 和 Corepack 的默认 registry。清空并保存后，新任务恢复项目或工具的默认配置。作用域专用源、锁文件中固定的外部下载地址，以及 Electron 等工具单独配置的二进制下载源仍由对应工具处理。网络和 DNS 可按宿主机环境配置，见[部署手册](../deploy/README.md#构建依赖出口)。

## 检查与测试

```bash
CI=true npm run typecheck
CI=true npm run test -w @builder/server
CI=true npm run test:platform -w @builder/server
CI=true npm run test:ssh -w @builder/server
CI=true npm run test:project-delete -w @builder/server
CI=true npm run build -w @builder/web
```

平台集成测试使用临时目录和本任务独占的本地 Git HTTP fixture，不访问真实外部仓库。源码编译、集成测试、浏览器交互、容器验收、生产部署分别记录，不能互相代替。

管理员打开后台时及后台页面可见期间每 15 分钟检查一次旧版本。按项目和构建编号判断：成功发布、产物未被停用、测试状态不是“不通过”的构建是有效版本（待测试也计入）。默认保留最近 10 个有效版本。比最新有效版本更早的失败、取消、产物停用或测试不通过的构建，以及排在第 11 位及以后的有效版本，进入清理建议。没有有效版本时不提示；排队、运行、停止中及比最新有效版本更晚的失败记录不会进入方案。每次弹窗只针对一个项目，取消不删除，确认前服务端重新核对清单。清理沿用构建删除流程，不动项目本身和独立备份。管理员未确认时允许暂时超过 10 个。
