# Git SSH 拉取交接

## 管理页面

管理员在设置页生成或导入 SSH 密钥，将公钥添加到代码托管平台，再在项目配置中绑定该密钥。SSH 项目缺少密钥时，构建弹窗对管理员显示“去配置”，对普通用户显示“请联系管理员配置”。HTTPS 仓库使用匿名拉取。界面交互详见 [UI 交接](ui-handoff.md)。

## 测试拉取与正式构建

- 页面“测试拉取”调用 `POST /api/projects/:id/test-fetch`，使用项目当前绑定的密钥和所选分支或标签。
- 正式构建使用任务快照中的密钥，开始执行时从远端拉取所选分支或标签，并记录实际使用的提交。
- 首次成功连接后，后端记录该主机和端口的公钥。后续公钥不匹配时拒绝拉取。合法轮换时，管理员先从可信渠道核实新公钥，再通过主机管理接口更新记录。接口权限、凭据生命周期和旧客户端兼容要求见 [SSH 接口契约](ssh-key-api.md)。

## Docker 网络

Git 拉取和打包共享部署方的 Docker 网络设置。排查拉取失败时，先区分域名解析或连接失败、主机公钥变化，以及项目密钥无仓库读取权限。服务器配置见[部署手册](../deploy/README.md)，隔离要求见[运行说明](runtime.md)。
