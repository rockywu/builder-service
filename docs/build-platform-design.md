# 构建平台设计：收敛版

本文取代此前设计，作为当前范围基线。当前已完成代码脚手架及登录功能，具体实施状态见第 11 节；构建业务尚未实现，服务尚未部署。没有列入本期范围的功能，不自动纳入后续实施。

## 1. 用户明确提出的需求

1. 服务部署在 Linux，使用 Node.js 开发。
2. 支持 Git 拉取、更新和切换分支。
3. 执行仓库内的 Node.js 和 Bash 构建脚本。
4. 支持多个构建同时执行，管理员可设置并行数量，超出数量的任务按入队顺序等待执行。
5. SQLite 持久化，使用 `better-sqlite3` 操作；直接使用一张表作为任务队列，不使用消息中间件。
6. 支持账号密码登录和用户管理；首次初始化默认管理员账号为 `admin`，密码为 `admin123456`。
7. 下载页面独立于管理端且无需账号密码认证，登录页提供明显下载入口。构建产物通过统一公开下载页面进入，按项目提供不同下载入口；项目页默认展示最新构建，支持按四种测试状态筛选。
8. 版本可人工标记：已测试（绿色）、待测试（黄色）、测试中（蓝色）、测试不通过（红色）。
9. 创建项目时支持上传项目图标，在项目列表、统一下载入口及项目下载页展示。
10. 已构建版本可手动删除；正在执行的任务可手动停止；待构建任务可手动删除。删除采用物理删除，同时清理该次构建独占的源码副本、文件和数据库记录。

后续增加其他脚本类型是扩展方向，本期只保持执行逻辑可增加类型，不实现其他语言或插件系统。

## 2. 最小业务流程与设计假设

管理员配置仓库地址、默认分支、工作目录、构建脚本和产物路径。登录用户刷新代码、选择分支并提交构建，任务进入 SQLite 队列。有空位时执行，成功后版本自动出现在公开页面，默认标记“待测试”。登录用户可修改四种测试状态，匿名访客只能查看公开版本和下载产物。

以下是为形成完整流程所采用的最小设计假设，尚不是用户逐项确认的需求：

- 一个团队使用，账号分为管理员和普通用户；普通用户共享项目可见范围。管理员管理用户、项目构建配置及并行上限，普通用户可触发构建、查看日志、修改测试状态。没有项目成员授权界面。
- 用户已明确公开下载页面及产物下载无需账号密码。构建成功后自动公开是本方案的收敛默认值，不增加人工发布审批；该规则仅适用于本平台配置的构建产物，不将现存私有产物自动迁入公开范围。
- “已测试”保留用户原始文字，按测试通过解释，与“测试不通过”区分。
- 本期面向受信任的团队仓库，不开放匿名构建任意仓库。

这些假设若不符合实际，只调整对应规则，不扩展整套工作流。

### 本期实现边界

以下为控制实施规模的设计默认值，不增加用户功能：

- 每个项目只维护一套当前构建配置。提交任务时保存快照，不建设多配置、配置版本管理或不同环境的配置体系。
- 一次构建执行项目配置的一份完整构建脚本，脚本内命令按顺序执行，任一命令失败即停止；多任务之间可以并行，平台不提供步骤拆分、可视化编排、条件分支或任务内并行。
- 一个成功构建对应一个版本，可以包含多个产物文件。平台按项目及任务序号自动生成唯一版本标识，不要求脚本写回版本号，不引入语义化版本、升级通道或版本晋级。
- 手动重新构建就是新建普通任务并排到队尾，不增加自动重试、从失败处续跑或独立重试状态。
- 基础资源额度、超时默认值和存储位置由部署配置管理；网页系统设置本期只暴露全局并行数。审计和备份保留必要记录与操作说明，不建设管理看板。

### 登录与公开访问（本轮明确要求）

- `/` 默认进入 `/login`，提供账号、密码输入及登录按钮；默认管理员 `admin / admin123456` 只在首次初始化数据库时创建，重启不能覆盖既有账号或密码。
- 密码使用带随机盐的哈希保存，浏览器通过 HttpOnly 会话 cookie 登录，支持退出和过期；登录失败提示账号或密码错误，不暴露账号是否存在。
- `/admin/*` 管理页面需要登录，服务端管理 API 同样校验会话，不能只依靠前端路由控制。
- 登录页提供“前往项目下载”入口；`/downloads` 和 `/downloads/:projectSlug` 使用独立公开布局，匿名可访问，不调用登录校验接口，不跳转登录。
- 后续项目图标、公开版本查询及产物下载接口保持匿名可访问，用户、配置、源码与构建日志接口继续受认证保护。公开下载不要求账号密码。

## 3. 技术与部署

| 部分     | 本期选择                                              |
| -------- | ----------------------------------------------------- |
| 前端     | Vue 3 + TypeScript + Vite + Element Plus + Vue Router |
| 后端     | Node.js + TypeScript + Fastify                        |
| 数据库   | SQLite + better-sqlite3                               |
| 日志推送 | SSE                                                   |
| 部署     | 一台 Linux，Nginx 提供 HTTPS，systemd 管理服务        |

前端方案为此前提出的技术建议，不是额外业务需求。前端编译为静态文件，不运行开发服务器。

架构保持为一个 Node.js 应用，内部包含 API、任务调度和构建执行模块。数据库由一个专用 Worker 线程访问，构建使用独立进程及隔离环境。Worker 是进程内实现细节，不另建数据库服务。

不建设独立 Runner 服务、远程执行协议、多节点注册或容器管理平台。每任务独立工作目录，并使用一种固定的非特权容器运行环境隔离构建脚本；容器仅作为保护宿主机和凭据的执行手段，不提供镜像市场或任意挂载配置。具体选择一种受目标服务器支持的容器运行时即可。

首期由部署方配置一个含 Node.js、Bash 和实际打包所需工具的固定环境。Node.js/Bash 通过命令直接调用，不引入执行器插件、自动识别仓库技术栈或按项目在线安装运行时的功能。容器运行时和资源额度在实施构建模块时根据目标 Linux 服务器确定，不能据此另建环境管理产品。

## 4. 项目配置、Git 与脚本执行

- 创建项目表单支持可选的图标上传，不上传时显示统一默认图标。图标旁保留项目名称，不只靠图片识别项目。
- 图标按小图片处理：第一期允许 PNG、JPEG、WebP，大小上限建议 2 MB、总像素上限建议 1600 万；这是实现默认值，不增加图片编辑或裁剪功能。服务端校验实际内容并安全解码、重编码为静态图片，拒绝 SVG、伪装文件及超限图片，不能只检查扩展名或客户端 MIME。
- 上传随管理员创建项目操作提交，校验身份和 CSRF；使用服务器生成的存储键，将文件存于独立图标目录，数据库仅保存引用。图标明确属于公开项目资料，通过受控图片地址展示，不接受客户端提供文件路径。创建失败不留下项目对临时文件的无效引用，未引用文件按有限范围清理；备份包含项目引用的图标。
- 项目保存仓库地址、默认分支、构建脚本、工作目录、产物路径和超时时间。
- 工作目录是构建脚本在仓库内的执行目录，填写相对仓库根目录的路径（以 `./` 开头，不允许 `..`）：普通项目为 `./`，Monorepo 子项目如 `./apps/web`。产物路径相对工作目录解析。
- 拉取/更新用于获取远端代码；切换分支用于选择新任务构建的分支，不改变已经运行的任务。
- 入队前固定完整 commit SHA 和构建配置快照；排队期间分支更新不能改变本次任务内容。获取失败明确报错，不静默使用旧代码。
- 每任务独立源码、依赖和输出目录，允许同仓库的多个分支并行构建。第一期独立克隆，不做共享 Git 缓存。
- 构建脚本由管理员在配置页完整填写（多行 Bash），任务执行时写入任务目录，在工作目录下以 `bash -e` 运行；可包含 `npm ci`、`npm run build`、`node scripts/build.mjs`、`bash scripts/build.sh` 及 `export` 等，任一命令返回非 0 即判定失败。日志逐条回显执行的命令，失败时标明出错命令。
- 构建脚本仅由管理员配置，并在任务容器内执行，不给匿名或普通用户提供任意宿主机命令执行入口。Git 和进程调用使用参数数组，不能拼接分支名等输入为 shell 命令。
- 构建日志写文件，页面以纯文本显示；产物必须满足配置要求，脚本退出成功但没有必需产物仍判为失败。

Linux 只构建其工具链支持的目标。Windows/macOS 专属工具链、签名和公证不属于本期。

## 5. SQLite 队列与并行控制

`build_jobs` 同时保存排队、运行及已结束的任务，不再增加单独的 queue 表。

- 用递增整数作为入队序号；按序号领取 queued 任务。序号允许间隔，并行任务不保证完成顺序。
- `max_concurrent_builds` 保存到配置表，默认 1，管理员可修改为有效正整数。
- 上限为 3 时，最多 3 个任务占用执行槽位，其余按顺序等待。准备代码和收集产物也占用槽位。
- 调高后补位；调低后让现有任务继续，直到占用数低于上限才启动下一项。
- 入队、结束、修改上限时唤醒调度；约每 2 秒轮询兜底。本地通知不是队列，数据库才是事实来源。
- 单调度器且循环不重入，进程独占锁防止服务被重复启动后出现两个调度器。

一次领取通过 `db.transaction(fn).immediate()` 在一个同步短事务内完成：读取并行上限 → 统计占用任务 → 选择最早 queued 任务 → 条件更新为 starting → 提交。提交成功后才启动构建，事务内不拉代码、不运行脚本、不等待网络。

queued、starting、running、collecting、succeeded、failed、canceling、canceled、recovering 为内部任务状态。starting、running、collecting、canceling、recovering 均占用槽位；超时作为失败原因记录。不得仅凭内存计数判断空位。

等待任务提供“删除”，执行中的任务提供“停止构建”。停止时进入 canceling，先请求正常退出，超时后强制终止该任务容器及整个进程树；确认停止后记为 canceled 并释放槽位。停止本身保留任务及日志，便于查看结果；需要清理时再执行物理删除。停止与正常完成竞争时，以条件更新确认唯一结果，不能把已经完成的版本改成取消。

服务重启后保留等待顺序，先核对遗留执行进程/容器。首期不实现接管并继续运行旧任务：对尚未结束的遗留执行请求停止，确认停止后将任务记为中断失败，再继续等待队列；已经完成产物提交但尚未记录结果的任务，先按第 7 节核对文件和数据库状态，不能重复执行或直接清理。状态未确认前保留占用；确定性的执行标识防止启动响应丢失导致重复执行。内部 recovering 状态仅用于恢复核对，不代表断点续跑。

## 6. better-sqlite3 与最小数据结构

使用一个本机 SQLite 文件，一个数据库 Worker 和一个长期连接。`better-sqlite3` 同步查询在 Worker 内执行，避免阻塞 HTTP 事件循环；数据库操作串行，不妨碍外部构建进程并行。

| 表              | 职责                                                                                     |
| --------------- | ---------------------------------------------------------------------------------------- |
| users           | 账号、密码哈希、管理员/普通用户、启用状态                                                |
| sessions        | 登录会话哈希、用户 ID、有效期                                                            |
| projects        | 项目名称、图标存储键（可空）、Git 地址、默认分支、工作目录、构建脚本、产物规则和凭据引用 |
| build_jobs      | 入队序号、项目、提交及配置快照、状态、执行标识、发起人、时间、退出码、日志路径           |
| releases        | 构建任务、版本标识、测试状态、状态版本号、创建时间                                       |
| artifacts       | 版本 ID、存储键、文件名、大小、SHA-256                                                   |
| system_settings | 全局并行上限                                                                             |
| audit_logs      | 用户/权限及配置变更、测试状态变化的操作者、时间与脱敏摘要                                |

不建立项目成员、独立构建配置版本、发布审批或凭据管理界面的业务表。Git 凭据使用部署时配置的受限文件，项目只记录引用，不做凭据管理产品。

上述八张表分别承担账号、会话、项目、任务、版本、文件、设置和必要追溯职责。本期按需求逐步创建；不为减少表数将会话混入账号或将文件清单塞入任务状态，也不预建未使用的扩展表。只有 `build_jobs` 承担队列职责，其余表不是额外队列。

- 启用 WAL、foreign_keys、synchronous=FULL 和有界 busy_timeout；使用参数化预编译语句和分页。
- 建立 `(status, queue_sequence)` 索引；用户名、版本标识、同一构建对应版本等设置唯一约束。
- 业务事务整体在 Worker 内完成，禁止在事务中 await 或让多个调用交错执行同一事务。
- 默认单表查询；有限批量读取后由应用组装，避免 N+1。需要一致读取时使用短事务；不包含联表 SQL。
- 创建任务使用幂等键，状态修改使用条件更新；响应超时不能直接假定写入失败再重复写入。
- Worker 不可用时停止新任务领取，明确返回服务异常；不无限排队或偷偷增加写入路径。
- 文件存产物和日志，数据库仅存元数据。在线备份使用 `db.backup()`，保留必要的数据库迁移和恢复措施。
- 在目标 Linux 安装兼容 Node.js 的 better-sqlite3 原生模块，不能复制 macOS node_modules 部署。

## 7. 公开版本与测试标记

本期只有构建状态和测试状态，不增加草稿、审批、发布、撤下这套状态机。

| 测试状态   | 展示颜色 |
| ---------- | -------- |
| 已测试     | 绿色     |
| 待测试     | 黄色     |
| 测试中     | 蓝色     |
| 测试不通过 | 红色     |

状态同时显示文字，不能仅靠颜色。修改时保存操作者及时间，并用版本号防止覆盖其他用户刚保存的状态。

版本在产物完整保存后自动公开；默认待测试，不将命令成功等同于测试通过。不做推荐版本、测试报告或发布说明编辑器。

公开下载页面结构：

- 统一入口 `/downloads`：展示项目图标、名称及各项目的下载入口。
- 项目入口 `/downloads/:projectSlug`：展示项目图标和名称，只展示该项目的构建版本及产物，提供版本标识、构建完成时间、测试状态、文件名和下载按钮。
- 默认不按测试状态过滤，展示最新的成功构建版本，其余历史版本按构建完成时间倒序排列并分页；时间相同按入队序号倒序稳定排序。失败或尚未完成的构建没有可下载版本，不作为“最新版本”。
- 筛选项为“全部、已测试、待测试、测试中、测试不通过”。选择状态后只查询该项目符合状态的版本，仍按上述顺序展示，切换筛选时回到第一页。即使最新版本为待测试或测试不通过，也如实展示，不自动替换成已测试版本。
- 筛选在服务端执行后再分页，不能只筛选当前页。没有符合条件的版本时显示“暂无符合条件的版本”；没有成功构建的项目显示“暂无可下载版本”。

产物先写临时目录，校验后在同文件系统原子重命名，再事务写入版本及文件记录。文件和数据库不能组成单一事务，必须核对崩溃产生的孤立文件或缺失文件；未完成或损坏的版本不能作为正常版本展示或下载。

公开接口只返回允许公开的字段，日志、源码、凭据、宿主机路径不公开。下载按文件 ID 查表定位，禁止用户路径拼接；使用附件下载，不在主站直接执行产物中的 HTML/JS。版本文件不可原地覆盖，重新构建生成新版本。

### 手动停止与物理删除

| 对象 | 操作 | 结果 |
| --- | --- | --- |
| 待构建任务 | 删除任务 | 从队列移除，并清理该任务文件及记录；不保留软删除任务 |
| 正在构建的任务 | 停止构建 | 确认执行终止后释放槽位，保留任务和日志；随后可以删除 |
| 已完成版本 | 删除版本 | 清理版本、产物及其对应构建任务的文件和数据库记录 |
| 失败或已停止任务 | 删除任务 | 清理源码工作区、残留产物、日志及任务记录 |

删除按单次构建为单位，不单独删除版本中的某一个文件。页面在执行物理删除前显示项目、任务/版本及清理范围，要求一次明确确认；不增加回收站或恢复按钮。

沿用现有两种角色，采用以下权限默认值：管理员可停止和删除任意任务或版本；普通用户可停止、删除自己发起的任务及其生成版本。每次操作在服务端核验，不根据前端按钮或传入路径决定权限。公开下载页不提供删除或停止操作。

清理范围包括：

- 该任务独立克隆的源码目录（含 `.git`）、安装的依赖、临时工作目录和停止后残留的任务容器/专属卷。
- 该版本的全部产物、staging 临时文件、校验清单和构建日志。
- 对应的 artifacts、releases、build_jobs 记录，以及仅从属于该任务/版本的状态变更记录和审计明细；删除成功后不保留原对象的软删除行。

项目本身、图标、项目构建配置、用户、凭据和其他任务使用的共享资源不属于此次清理范围。“源码”指服务器为该任务克隆的副本，不操作远程 Git 仓库。物理删除指在线文件系统删除文件、SQLite 使用 DELETE 删除记录，不承诺存储介质覆写；已经下载到访客设备的文件及先前生成的备份不在该次在线删除范围内。

删除过程必须防止与领取、构建回调、下载及备份竞争：

1. 在短事务中校验权限、任务状态与关联记录，将该任务标记为正在清理。该标记只用于跨文件/数据库操作的临时恢复，成功后随任务记录一起物理删除。调度器只领取未进入清理流程的 queued 任务。
2. 删除等待任务与领取使用同一条件更新边界；如果已经被领取，删除返回状态冲突，页面更新为可停止，不强行删除运行目录。对任何可能仍在执行或恢复核对的任务，必须先确认执行终止。
3. 版本进入清理流程后立即从公开列表排除，拒绝新的下载；受控下载流结束或关闭、备份对该文件的读取结束后，再释放文件。以任务执行标识和状态检查拒绝迟到回调，防止重新生成被删除记录。
4. 按服务端记录的任务专属路径清理，校验所有权和目录边界，不跟随越界符号链接；文件已不存在按已清理处理。文件清理成功后，在事务中按外键依赖顺序删除关联记录及任务本身。
5. 任一步失败时明确显示“删除未完成”，保留仅用于完成清理的记录及错误摘要，版本继续不可下载。服务重启或管理员再次删除时从剩余步骤继续；不能先删数据库记录再丢失文件位置，也不能把部分清理报告为完成。

删除成功的完成标准是：相关任务/版本数据库记录不存在、任务专属文件不存在、对应公开下载不可用。最后一个版本被删除时，项目入口保留并显示“暂无可下载版本”；删除最新版本后，下一条符合筛选条件的版本自然成为首条。

## 8. 必须保留的基础保护

以下用于保证上述需求正确运行，不作为可随意删除的扩展功能：

- 密码使用 Node.js 原生 scrypt 加随机盐哈希；HTTPS、安全会话 cookie、写接口 CSRF 校验和登录限流。管理员创建/禁用/删除用户、重置密码；不开放注册。禁用或权限变更及时撤销会话，保留可用管理员。删除用户需二次确认，物理删除账号并撤销其全部会话；不能删除当前登录账号或最后一个启用的管理员。该用户发起的构建任务、版本测试状态记录和审计日志保留原账号名，不随账号级联删除；同名重新创建视为新账号。
- 服务端逐接口校验权限；匿名只访问公开版本。单团队共享项目是明确假设，不能在未来存在隔离要求时继续复用此权限模型。
- 构建使用非特权执行环境，隔离宿主服务、数据库、Git 凭据及其他任务；不挂载容器引擎 socket。限制资源、时长和日志体积，限制访问管理网络及元数据端点。
- 构建账号与服务凭据分离；凭据不进入代码、日志或公开产物。校验 Git 远端及 SSH 主机密钥；子模块和 LFS 本期不自动启用。
- 校验工作目录和产物边界，拒绝目录穿越、越界符号链接及非普通文件。必要产物缺失、超出额度或磁盘不足明确失败，不产生伪成功版本。
- 使用安全文件权限；按授权的单次构建范围清理文件，已公开版本只在明确执行删除操作后清理。磁盘不足停止领取并显示错误，不建设容量监控平台。
- 保留简明备份/恢复操作说明，数据库快照与其引用的不可变产物一起备份，保护凭据文件；备份期间不能清理所引用文件。

## 9. 本期页面与验收范围

页面仅包括：登录、项目/构建配置、构建队列与日志详情、版本列表及状态修改、用户管理、并行数量设置、统一公开下载入口和各项目下载页（最新构建、四种测试状态筛选、产物下载）。设置可以合并到现有页面，不强制每项独立页面。

前端现有菜单是入口骨架，不据此增加独立模块：项目内完成配置和发起构建，队列页进入任务日志及按状态停止/删除任务，版本列表直接修改测试状态或删除版本，用户页完成创建/禁用/删除/密码重置，并行数只需一个设置项。公开端只需项目入口和项目版本页，不增加首页仪表盘、统计报表或单独的发布中心。

P0：完成真实 Git → 入队 → Node.js/Bash 执行 → 产物 → 公开下载 → 四色状态修改闭环；并行上限为 2 时提交 5 个任务，验证最多两个占用且 FIFO 补位；同仓库不同分支输出不混淆。同步验证匿名权限、凭据隔离和路径边界。

P1：验证调高/调低上限、失败/超时/取消、重启恢复、重复请求、文件与数据库提交中断、账号禁用与删除、状态并发修改、下载完整性，以及一次备份恢复。公开下载验证项目入口不混入其他项目版本、默认最新排序、四种状态筛选与分页、状态修改后的查询结果及空列表。不得以编译通过替代这些验收。具体测试配置及限时遵循 AGENTS.md。

项目图标验收包括：带图标创建后正确展示、不上传时默认展示、无权限上传被拒绝、伪装或超限图片被拒绝、创建失败不产生无效引用。以上是待执行验收标准，尚未测试。

停止及物理删除属于本期 P0/P1 验收：验证排队删除与调度领取竞争、运行任务及子进程实际停止后补位、无权限操作被拒绝、已完成/失败/停止任务的文件与关联记录清理、删除最新/最后一个版本后的展示、删除期间下载及备份竞争、部分清理失败与重启续清理、迟到回调不复活记录。以实际文件和数据库读回确认完成，不能只验证 HTTP 成功或页面隐藏；同时验证同项目其他任务、项目图标及远端仓库不受影响。
